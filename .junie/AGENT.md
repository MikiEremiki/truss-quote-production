# Руководство для AI-агентов и разработчиков (AGENT.md)
## MiTek Costing & Production Suite

Данный документ содержит контекст предметной области, архитектурные правила, структуру проекта и инструкции для AI-агентов и инженеров-разработчиков, сопровождающих и развивающих данный репозиторий.

---

### 1. Предметная область и назначение системы

Проект разработан для компании **«ДревКаркас»** и решает задачи автоматизации производственно-экономического цикла изготовления деревянных ферм на металлических зубчатых пластинах (МЗП) и стропильных систем:
1.1. **Инженерный парсинг**: извлечение геометрических, прочностных и материальных спецификаций из выгрузок ПК **MiTek Pamir** (`.xlsm` / `.xlsx`).
1.2. **Калькуляция себестоимости и КП**: расчет прямых затрат (доска C24, МЗП T150, защитная пропитка, прирезка, запрессовка на прессе, проектирование, крепеж, логистика) с настраиваемой маржинальностью и формированием коммерческого предложения.
1.3. **Подготовка производства**:
   - Оптимизация 1D-раскроя пиломатериала в хлысты заданной длины (мм) с минимизацией отхода;
   - Послойная комплектация ферм для запрессовочного стола;
   - Спецификация зубчатых пластин по типоразмерам и узлам.

### 4. Ключевые бизнес-правила и формулы

При любых модификациях расчетного ядра **строго соблюдать** следующие правила:

#### 4.1. Стандарты округления и точности (см. ADR-006):
- **Линейные размеры и длины**: целые числа в миллиметрах (`int(round(...))`, $0$ знаков).
- **Площади** (скаты кровли, защитная пропитка, пластины МЗП): $м^2$ с точностью до **2 знаков** (`round(val, 2)`).
- **Объемы древесины**: $м^3$ с точностью до **4 знаков** (`round(val, 4)`).
- **Денежные суммы**: рубли с точностью до **2 знаков** (`round(val, 2)`).

#### 4.2. Антисептирование / защитная обработка:
- Рассчитывается от **фактической 4-сторонней площади поверхности всех заготовок** ($м^2$):
  $$S = \sum \left( \text{Qty}_i \times 2 \times (T_i + D_i) \times L_i \right)$$
  *(где $T$, $D$, $L$ выражены в метрах)*.
- **Запрещено** рассчитывать защитную обработку от кубатуры ($м^3$), если пользователь явно не запросил иное.

#### 4.3. Пластины МЗП:
- Все площади МЗП хранятся и тарифицируются в **$м^2$** ($1\text{ м}^2 = 100\text{ дм}^2$).

#### 4.4. Послойный учет ферм:
- Физическое число изготавливаемых на прессе ферм:
  $$\text{Total Layers} = \text{Quantity} \times \text{Plies}$$
- Трудозатраты и запрессовка рассчитываются на каждый физический слой.

#### 4.5. Классификация позиций:
- `truss` (Ферма на МЗП): пиломатериал + МЗП + сборка на прессе ($руб/м^3$) + прирезка ($руб/м^3$).
- `cut_timber` (Доска с прирезкой / Стропила): пиломатериал + прирезка ($руб/м^3$).
- `raw_timber` (Просто доска): только пиломатериал.

#### 4.6. Оптимизация 1D-раскроя (Bin Packing):
- Длина заготовочного хлыста задается в целых миллиметрах ($мм$, по умолчанию $6000\text{ мм}$).
- Учитывать толщину реза торцовочной пилы ($4\text{ мм}$).

### 5. Архитектура пакета `costing/` и фронтенда

#### 5.1. Модульный бэкенд (`costing/`):
- **`costing.core`**: доменные сущности (`TrussFrame`, `TimberItem`, 
 `PlateItem`), справочники ценовых политик ДК (`DK_PRICING_CATALOG`), профили клиентов и агентские ставки.
- **`costing.data_import`** (псевдоним `importers`): чтение Excel-книг 
 MiTek Pamir через `openpyxl`, нормализация геометрии и вычисление 4-сторонней площади заготовок.
- **`costing.calculator`**: ядро калькуляции себестоимости материалов 
  (доска, МЗП), трудоемкости работ, защитной обработки, проектирования, логистики и накладных расходов.
- **`costing.quote`**: генератор коммерческих предложений, 
  версионирование, скидки, агентские комиссии (`markup`/`margin`/`discount`), расчет НДС, экспорт в печатные формы/PDF.
- **`costing.workorders`**: наряды производства, послойный учет ферм 
  (`qty * plies`), 1D Bin Packing оптимизатор раскроя пиломатериала в хлысты заданной длины (мм).
- **`costing.api`**: REST API бэкенд на FastAPI, Pydantic-схемы 
  валидации (`schemas.py`) и маршруты (`routes.py`).

#### 5.2. Спецификация REST API маршрутов (`costing/api/routes.py`):
- `GET /api/info` — метаданные версии и программного комплекса;
- `GET /api/sample` — получение данных и расчетов эталонного проекта (Богородск 21);
- `POST /api/upload` — загрузка и парсинг нового файла выгрузки MiTek (.xlsm / .xlsx);
- `POST /api/costing/calculate` — расчет себестоимости и цен на материалы/услуги (вкладка «Калькулятор стоимости»);
- `POST /api/positions/calculate` — расчет сложности работ, антисептирования, прирезки и наценок по маркам (вкладка «Позиции»);
- `POST /api/cutting/optimize` — оптимизация 1D раскроя пиломатериала на хлысты в мм (вкладка «Раскрой»);
- `POST /api/financials/calculate` — расчет P&L, скидок, агентских вознаграждений и НДС (вкладка «P&L Финансы»);
- `POST /api/calculate` — комплексный пересчет себестоимости и раскроя (обратная совместимость);
- `POST /api/quote` — генерация структурированного коммерческого предложения;
- `POST /api/workorders` — генерация производственных нарядов и карт раскроя для цеха.

#### 5.3. Модульный No-Build SPA фронтенд (`web/static/js/`):
- `app.js` — точка входа (`<script type="module">`), первичная инициализация и запуск приложения;
- `modules/state.js` — централизованное хранилище реактивного состояния (`appState`, `getAppState`, `setAppState`);
- `modules/api.js` — сетевой сервисный слой (асинхронные HTTP-клиенты к эндпоинтам `/api/*`);
- `modules/helpers.js` — вспомогательные функции интерфейса (индикатор загрузки `showLoading`, форматирование `fmtRub`);
- `modules/controllers.js` — контроллеры диспетчеризации событий по вкладкам и оркестрация пересчетов;
- `modules/renderers/` — специализированные рендереры интерфейса:
  - `summary.js` — сводка проекта и геометрия скатов/ферм;
  - `positions.js` — таблица позиций и индивидуальная сложность;
  - `costing.js` — калькулятор себестоимости и цен материалов;
  - `cutting.js` — интерактивные карты раскроя хлыстов;
  - `specs.js` — ведомости пиломатериала и пластин МЗП;
  - `financials.js` — управленческий отчет P&L;
  - `quotes.js` — коммерческое предложение;
  - `index.js` — единая точка экспорта рендереров.

### 6. Правила для AI-агентов при внесении изменений

#### 6.1. Автономность и No-Build
Не добавлять тяжелые npm/node_modules или внешние сборщики (Webpack/Vite). Все JS-модули работают нативно через браузерный стандарт ES6 Modules.

#### 6.2. Консоль Windows и кодировки
Никогда не использовать русскоязычный `echo` внутри `start_server.bat` и не добавлять `chcp 65001`. Все сообщения должны выводиться из Python через `WriteConsoleW`.

#### 6.3. Верификация
После любых правок в логике расчетов, моделях или API запускать полный набор автоматических тестов:
```bash
uv run python -m unittest discover tests
```

#### 6.4. Сохранение обратной совместимости API и целостности модулей
При модификации схем или структуры ответа эндпоинтов синхронизировать вызовы в `modules/api.js`, контроллеры в `modules/controllers.js` и соответствующие рендереры в `modules/renderers/`. Полнофункциональный эндпоинт `POST /api/calculate` должен сохраняться для обратной совместимости.

#### 6.5. Обязательная синхронизация документации (Definition of Done)
Любая задача по добавлению фичи, изменению API, бизнес-логики или структуры интерфейса считается завершенной ТОЛЬКО после актуализации соответствующей документации:
- При добавлении/изменении эндпоинтов — обновить `docs/API.md` и `costing/api/schemas.py`.
- При архитектурных решениях или смене подходов — зафиксировать новый ADR в `docs/ADR.md`.
- При изменении модульной структуры файлов или потоков данных — синхронизировать `docs/ARCHITECTURE.md` и `.junie/AGENT.md`.

#### 6.6. Обязательный финальный шаг в планах задач (Delivery Plan)
При формировании любого плана реализации фичи или доработки (Delivery Plan) последним шагом перед сдачей задачи ВСЕГДА должен быть шаг:
- `Step N: Актуализация проектной документации и ADR` (`docs/API.md`, `docs/ADR.md`, `docs/ARCHITECTURE.md`, `.junie/AGENT.md`).

Это гарантирует систематическое закрытие Definition of Done в рамках пошагового выполнения плана.
